# SuperMetroid3DS

A Nintendo 3DS port of the Super Metroid static recompilation
([SuperMetroidRecomp](https://github.com/mstan/SuperMetroidRecomp)), built on
devkitPro/devkitARM with libctru.

> **⚠️ Status: the frontend runs. The game does not.**
>
> The port builds, boots and renders under Azahar. The recompiled core is **not
> linked** — it needs a fiber backend the 3DS does not yet have (ticket T027).
> What you see on screen is a test pattern that exercises the real frame,
> scaling and input paths, not Super Metroid.
>
> **No ROM is included and none will ever be.** See [Legal](#legal).

---

## What game this is

**Super Metroid** (1994, Nintendo) as released for the Super Nintendo. The
recompilation upstream targets the **Japan** revision, and that is the ROM this
port expects.

Because this port runs the original compiled code, the game *is* Super Metroid —
same behaviour, same graphics, same timing. Nothing here reimplements the game
logic.

## What this project is not

- **Not an emulator.** No interpreter, no JIT, no dynamic recompilation. The
  original game code is translated ahead of time into native ARM11 machine code.
- **Not a ROM distribution.** See [Legal](#legal).
- **Not finished.** See [Status](#status--measured).

## How it works

The upstream project provides a static recompilation of Super Metroid as
hand-written C plus a large set of generated dispatch shards. This port:

1. **Uses that core read-only, from outside the repository.** Upstream is never
   vendored as a submodule and never edited in place. See
   [The upstream rule](#the-upstream-rule).
2. **Writes its own 3DS frontend** — `frontend/3ds/` — for video, input and
   audio, and its own platform shim at `platform/3ds/`.
3. **Compiles the generated core from the ROM.** `src/gen/` (~88 MB of C across
   116 files) is generated by upstream's own tooling and is never committed,
   because it is derived from copyrighted ROM data.

### The upstream rule

Upstream is consumed read-only from a path outside this repository. That is not
fastidiousness; it is a response to a specific failure:

> The DS attempt checked out upstream as a submodule and edited it directly.
> A libnds macro, `PPU_T0_DECL`, was injected into
> `snesrecomp/runner/src/snes/ppu.c`. It does not compile on any other platform,
> and because the edit lived in another tree, **it never appeared in a diff of
> this repository**. It is preserved at
> `legacy/patches/0001-nds-ppu-t0-decl.patch` on the `ds-legacy` branch as
> evidence, not as a patch to apply.

Where a change genuinely cannot be expressed in `frontend/3ds` or `platform/3ds`,
it goes in `patches/NNNN-*.patch`. That chain is currently **empty**, which is
the intended state — see `make prepare`.

## Status, measured

The port is early. What exists, and what was actually measured:

| Claim | Evidence |
|---|---|
| Core compiles for ARM11 — 71 of 80 translation units, 0 errors | `docs/3DS-PORT-STUDY.md` |
| `.3dsx` builds and links | `make docker-build`, 121 KB artifact |
| Boots and renders under Azahar, terminates on cue | `make test` — 120 frames, clean exit |
| Compiled core size | **extrapolated, ~28 MB from one measured bank** (T025) |
| Frame rate | **not measured** |
| Frame correctness vs PC | **not measured** (T030) |
| Audio | not wired to the core; no resampler (T029) |

Two claims this project explicitly does **not** make: that 3DS is "4–8× faster
than DS" for this workload, and that the port is playable. Both were unmeasured
at some point. The first is a clock-speed extrapolation, not a profile.

The honest blocker: the framework's cooperative scheduler needs `<ucontext.h>`,
which the 3DS newlib environment does not provide. Until a fiber backend exists,
`SM_WITH_CORE` stays **off** and the build refuses to link a core that cannot
work.

## Requirements

- Docker (all builds run in `devkitpro/devkitarm`)
- A legally obtained **Super Metroid (Japan, USA)** `.sfc`
- Optionally Azahar, for the headless gate

## Building

```bash
make setup     # prints the exact commands; also `make doctor` to check state
make docker-build
```

The build reads a read-only upstream checkout. Point `UPSTREAM` at it, or accept
the default path:

```bash
make docker-build UPSTREAM=/path/to/SuperMetroidRecomp
```

## Running it

```bash
make test      # build + headless gate under Azahar
```

`make test` asserts the port boots, renders exactly N frames and terminates at
frame N. It prints a note saying whether the core was linked, because a pass with
`with_core=0` says **nothing about Super Metroid**.

To run by hand:

```bash
xvfb-run -a /path/to/azahar build3ds/supermetroid3ds.3dsx
```

Drop the `.3dsx` on a 3DS SD card to run it on hardware. There is no audio to
hear yet and no game to play.

## Legal

This repository contains **no ROM, no ROM image, and no copy of Nintendo code**.

You must supply your own legally obtained copy of Super Metroid (Japan, USA).
The expected digest is in upstream's `rom_identity.txt`; `make doctor` prints both
the digest of the file you have and the one upstream expects.

The game is copyrighted by Nintendo; this project is an unofficial port and is
not affiliated with or endorsed by Nintendo.

## Layout

```
SuperMetroid3DS/
├── CMakeLists.txt          3DS build: core lib + frontend
├── Makefile                docker-build, regen, test, doctor
├── frontend/3ds/           the 3DS frontend — all code specific to 3DS lives here
│   ├── 3ds_main.c          entry, frame loop
│   ├── 3ds_render.c        RGB565 present, integer letterbox
│   ├── 3ds_input.c         HID -> SNES pad word
│   └── 3ds_audio.c         PCM -> ndsp
├── platform/3ds/           replaces the framework's SDL include boundary
├── patches/                the upstream patch chain (currently empty)
├── scripts/gate-headless.sh  the behavioural gate
├── docs/
│   ├── 3DS-PORT-STUDY.md   the measured feasibility evidence
│   ├── VISION.md           problem, solution, value
│   ├── REQUIREMENTS.md     functional + non-functional
│   ├── ROADMAP.md          backlog
│   ├── DESIGN.md           3DS hardware specification
│   └── QUALITY_GATES.md    what is and is not enforced
└── aes/                    AES tracking (gitignored — not published)
```

Everything under `frontend/` and `platform/` is this port's own code. Everything
about Super Metroid comes from upstream, read-only.
